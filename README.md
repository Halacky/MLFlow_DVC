# Iris MLOps Pipeline (DVC + MLflow + Docker + CI)

Minimal, but complete MLOps project for the Iris classification task.  
The project demonstrates:

- Reproducible experiments
- Data and model versioning with DVC
- Automated pipeline (prepare → train → evaluate)
- Experiment tracking with MLflow
- Containerization with Docker
- Basic data tests (Pytest)
- CI pipeline (GitHub Actions)

---

## Installation & Quick Start

### 1. Clone the repository

```bash
git clone <YOUR_REPO_URL>.git
cd <REPO_FOLDER>
```

### 2. (Optional) Create and activate virtual environment

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Get data (via DVC or script)

If you already use a DVC remote with data:

```bash
dvc pull
```

If not, you can (once) generate `data/raw/iris.csv` with:

```bash
python src/download_data.py
dvc add data/raw/iris.csv
git add data/raw/iris.csv.dvc data/.gitignore
git commit -m "Add iris dataset via DVC"
```

### 5. Run the full pipeline

```bash
dvc repro
```

This will sequentially run the stages:

1. `prepare` → create `data/processed/train.csv`, `data/processed/test.csv`
2. `train`   → train model, log to MLflow, save `models/model.pkl`
3. `evaluate` → evaluate on test, log metrics and `evaluation_report.txt` to MLflow

## Pipeline Description

The pipeline is defined in `dvc.yaml` and uses `params.yaml` for configuration.

### Parameters (`params.yaml`)

```yaml
prepare:
  test_size: 0.2
  random_state: 42

train:
  model_type: "logreg"  # "logreg" or "rf"
  random_state: 42
  logreg:
    C: 1.0
    max_iter: 1000
  rf:
    n_estimators: 100
    max_depth: 5
```

### Stages

#### 1. `prepare`

- **Script:** `src/prepare.py`
- **Inputs:**
  - `data/raw/iris.csv`
  - `params.yaml` (`prepare.*`)
- **Outputs:**
  - `data/processed/train.csv`
  - `data/processed/test.csv`
- **Logic:**
  - Load raw Iris dataset
  - Split into train/test with fixed `test_size` and `random_state`
  - Save splits as CSV

#### 2. `train`

- **Script:** `src/train.py`
- **Inputs:**
  - `data/processed/train.csv`
  - `data/processed/test.csv`
  - `params.yaml` (`train.*`)
- **Outputs:**
  - `models/model.pkl`
- **Logic:**
  - Load train/test data
  - Select model type: Logistic Regression or Random Forest
  - Train model with given hyperparameters and random state
  - Evaluate on test set (accuracy)
  - Log parameters, metric (`accuracy`), and artifacts to MLflow
  - Save model to `models/model.pkl`

#### 3. `evaluate`

- **Script:** `src/evaluate.py`
- **Inputs:**
  - `models/model.pkl`
  - `data/processed/test.csv`
- **Outputs:**
  - `evaluation_report.txt`
- **Logic:**
  - Load trained model and test data
  - Compute metrics (accuracy, macro F1)
  - Print and save a text classification report (`evaluation_report.txt`)
  - Log additional metrics and the report as an artifact to MLflow
  - (Optionally, could be extended to register the model in MLflow Model Registry)

## MLflow: Experiments & UI

The project uses MLflow for tracking runs, parameters, metrics and artifacts.

In `train.py` and `evaluate.py`:

- Tracking URI: `sqlite:///mlflow.db`
- Experiment name: `iris_classification`
- Artifacts are stored under `mlruns/`.

### Running MLflow UI

From the project root:

```bash
mlflow ui --backend-store-uri sqlite:///mlflow.db
```

Open in your browser:

- http://127.0.0.1:5000

You will see:
- Runs for training and evaluation
- Logged parameters (e.g. model type, hyperparameters)
- Metrics (accuracy, macro F1)
- Artifacts (model pickle, evaluation report)

## Docker Usage

The project includes a `Dockerfile` to run the pipeline in a container.

### Build the image

```bash
docker build -t mlops-iris:latest .
```

### Run the pipeline inside the container

```bash
docker run --rm -it mlops-iris:latest
```

By default, the container executes:

```bash
dvc repro
```

If you want to persist MLflow data outside the container, mount volumes:

```bash
docker run --rm -it \
  -v $(pwd)/mlruns:/app/mlruns \
  -v $(pwd)/mlflow.db:/app/mlflow.db \
  mlops-iris:latest
```

## Testing (Pytest)

Basic data quality checks are implemented with Pytest in `tests/test_data.py`:

- Raw data file exists
- Processed train/test files exist
- Raw dataset is not empty
- Train + test sizes equal raw size
- No missing values in processed data

### Run tests

```bash
pytest
```

## CI/CD (GitHub Actions)

A simple CI pipeline is configured in `.github/workflows/ci.yml`.

On each push or pull request to `main`/`master`, the workflow:

1. Checks out the repository
2. Sets up Python
3. Installs dependencies from `requirements.txt`
4. Runs (optionally) `dvc pull` to fetch data from remote (if configured)
5. Runs `dvc repro` to execute the pipeline
6. Runs `pytest` to execute tests

You can view CI status on the “Actions” tab of your GitHub repository.

---

## Reproducibility

To fully reproduce the results on any machine:

1. Clone the repository
2. Create/activate a virtual environment (optional)
3. Install dependencies from `requirements.txt`
4. Pull data via `dvc pull` (if using remote)
5. Run `dvc repro`

With fixed random seeds (`random_state` in `params.yaml`) and fixed versions of dependencies, training and evaluation should produce the same metrics (within small numerical variations).
